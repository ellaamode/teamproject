금융규제통합조회 (가칭)

금융관계법령 규제정보 통합조회 서비스

정의 배경 팀 기능 데이터 아키텍처 구조 고민

1. 무엇을 만드는가?

금융규제통합조회는 입법예고, 법령개정, 법령해석, 비조치의견을 한 곳에 모아 법령 목차와 검색으로 찾아볼 수 있게 하는 서비스입니다. 금융회사 업무담당자가 스스로 최신 규제 현황을 검토하는 단계를 지원합니다.

2. 왜 필요한가?

금융회사 현업에서 기술적인 이슈를 제외하면 가장 큰 제약은 금융규제입니다. 법령의 개정과 최신 해석 사례가 여러 곳에 흩어져 있고, 금융당국이 제공하는 페이지도 찾아보기 번거롭습니다.

법령·규정의 개정, 그 해석 사례, 비조치의견은 실제 업무와 가장 밀접하게 맞닿아 있는 정보인데도, 지금은 업무담당자가 이를 스스로 파악하기 어려운 구조입니다.

3. 누가 만드는가?

양정모 양지선 이수정 김한룡 최은정

4. 어떤 기능을 제공하는가?

법령 목차를 따라 조문 단위로 찾아보거나, 통합검색·상세검색으로 원하는 자료를 찾을 수 있습니다. 해석·비조치의견이 인용한 조문은 자동으로 추출해 연결하고, 검색 결과는 관련도 순으로 보여줍니다.

법령 목차 탐색

법령의 장·절·조 구조를 그대로 따라가며 조문 단위로 관련 자료를 확인합니다.

통합검색

검색어 하나로 법령·입법예고·행정지도·법령해석·비조치의견을 한 번에 찾습니다.

상세검색

문서 유형·기관·기간·법령명을 조합해 정확하게 좁혀 찾습니다.

사례 상세보기

질의요지·회답·이유 등 원문 내용을 그대로 확인합니다.

인용 조문 연결

해석·비조치의견이 인용한 조문을 자동으로 추출해 연결합니다.

관련도 정렬

검색어와 얼마나 관련 있는지 순서대로 결과를 보여줍니다.

5. 어디서 가져오는가?

원천가져오는 것방식
법제처 국가법령정보 API조문, 개정이력공식 Open API
국민참여입법센터 API입법예고공식 Open API
금융규제·법령해석포털법령해석, 비조치의견REST 호출(공식 API 아님)

법제처 API와 국민참여입법센터 API는 인증키 기반의 정식 Open API입니다. 금융규제·법령해석포털은 공식 API가 없지만, 개발자도구 네트워크 탭으로 실제 요청을 확인한 결과 selectReplyCasePastReplyList.do(목록)와 LawreqDetail.do(상세)가 이미 구조화된 JSON·HTML을 반환하는 내부 엔드포인트라는 걸 확인했습니다.

화면을 다시 해석하는 크롤링 대신, 서버가 원래 반환하도록 만들어진 값을 그대로 받는 REST 호출을 택해 무료 배포 환경에서도 안정적으로 실행됩니다.

6. 서비스 아키텍처

수집한 데이터는 PostgreSQL에 원본으로 저장하고, 해석·비조치의견이 인용한 조문을 자동으로 추출해 연결합니다. FastAPI가 이 데이터를 조회·검색해 API로 내려주고, React 화면이 결과를 보여줍니다. 프론트·백엔드·DB 모두 무료 요금제로 운영합니다.

7. 조문 중심으로 연결됩니다

법령은 장·절·조 구조로 저장됩니다. 법령개정·입법예고는 대상 조문이 데이터에 이미 명시돼 있어 조문과 바로 연결하고, 법령해석·비조치의견은 본문에서 인용한 조문을 자동으로 추출해 연결합니다.

erDiagram
  LAWS ||--o{ ARTICLES : has
  ARTICLES ||--o{ AMENDMENT_HISTORY : has
  ARTICLES ||--o{ BILLS : targeted_by
  ARTICLES ||--o{ ARTICLE_REFS : cited_by
  INTERPRETATIONS ||--o{ ARTICLE_REFS : cites

LAWS는 법령, ARTICLES는 조문, AMENDMENT_HISTORY는 개정이력, BILLS는 입법예고, INTERPRETATIONS는 법령해석·비조치의견입니다. 개정이력·입법예고는 조문에 바로 연결되고, ARTICLE_REFS는 "이유" 텍스트에서 자동 추출한 인용 조문으로 해석·비조치의견을 조문에 연결하는 테이블입니다.

예시로 보면

전자금융거래법 제23조(선불충전금의 관리) 하나에 무엇이 연결되는지입니다.

법령개정·입법예고는 데이터 자체에 대상 조문이 적혀 있어 바로 연결됩니다(흰 배경). 법령해석은 그런 항목이 없어서, "이유" 텍스트에서 "제23조"라는 인용을 자동으로 추출해 연결합니다(색칠된 배경). 같은 조문 하나에 서로 다른 방식으로 모인다는 게 핵심입니다. 실제 데이터에는 이 조문에 연결된 행정지도 사례도 하나 더 있는데, 행정지도는 아직 테이블 설계가 확정 전이라 이 다이어그램에는 넣지 않았습니다.

8. 고민중인 부분은?

"이유" 텍스트의 인용 표기 방식이 「」 없이 쓰이거나 "이 법", "관련 법령"처럼 애매한 지시어를 쓰는 경우가 있어, 정규식으로 못 잡는 사례가 남습니다. 이 실패 사례를 어떻게 줄이거나 보완할지 고민하고 있습니다.

자주 찾는 법령이나 조문을 사용자별로 등록해두고, 그 조건에 맞춰 화면을 개인화하는 방법도 고민하고 있습니다.

행정지도까지 함께 보여주고 싶은데, 금융위원회 행정지도와 금융감독원 행정지도가 서로 다른 사이트에 있고 수집 방식도 다릅니다. 두 기관의 데이터를 어떻게 하나의 체계 안에 자연스럽게 통합할지 고민하고 있습니다.
